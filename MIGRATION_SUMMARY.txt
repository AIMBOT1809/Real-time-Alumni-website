DATA FLOW SUMMARY
================================================================================

PEOPLE TAB:
User A → [Click People Tab]
      ↓
  Query: student_profiles, alumni_profiles, faculty_profiles
      ↓
  Filter: WHERE user_id != current_user
      ↓
  Display: Name, avatar, role, department
      ↓
  Action: [Connect] → POST /api/requests

CONNECTION REQUEST:
User A → [Click Connect]
      ↓
  POST /api/requests {receiverId: B}
      ↓
  Backend: INSERT connection_requests (sender=A, receiver=B, status=accepted)
      ↓
  Backend: CREATE conversation, INSERT participants
      ↓
  Socket: Emit "request_accepted" to User B
      ↓
  User B: See conversation in Inbox

INBOX TAB:
User → [Inbox Tab]
   ↓
  GET /api/conversations (with user.id header)
   ↓
  Query: SELECT conversations WHERE user IN conversation_participants
   ↓
  FOR EACH conversation:
    - GET other user's profile
    - GET last message
    - COUNT unread messages
   ↓
  Display: Conversations with avatars, names, last message, unread count

OPEN CHAT:
User → [Click Conversation]
   ↓
  GET /api/conversations/:id/messages (limit 50)
   ↓
  Load message history from database
   ↓
  Subscribe to: postgres_changes on messages table
   ↓
  On new message: Received via subscription, add to list
   ↓
  Display: Messages with timestamps, read status

SEND MESSAGE:
User → [Type and press Enter]
   ↓
  POST /api/conversations/:id/messages {text: "Hello"}
   ↓
  Backend: INSERT message (sender=user, created_at=now)
   ↓
  Backend: Socket emit to conversation room
   ↓
  Both users receive via:
    a) Socket.io (real-time broadcast)
    b) Realtime subscription (backup)
   ↓
  Message appears in chat instantly

REALTIME UPDATES:
When any user sends message in conversation:
  ↓
  Database INSERT on messages table
  ↓
  Supabase realtime trigger
  ↓
  All subscribed clients receive event
  ↓
  Frontend adds message to state
  ↓
  Component re-renders with new message
  ↓
  No page refresh needed
